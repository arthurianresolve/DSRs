A signature declares typed input and output fields. `Predict<S>` renders its prompt, sends it through an LM, and parses the response into `Predicted<S::Output>`.

## Install

```toml
[dependencies]
dspy-rs = "0.7.3"
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
anyhow = "1"
serde_json = "1"
```

These guides describe the repository checkout. A published crate may not yet include every documented API. For a local checkout, replace the version dependency with `dspy-rs = { path = "../DSRs/crates/dspy-rs" }`.

The default Cargo features are `data` and `cache`. For typed prediction without the heavy dataset and disk-cache dependencies, use `default-features = false`.

| Features | Dataset loading | Response caching | Execution history |
|---|---|---|---|
| Default (`data`, `cache`) | JSON/JSONL, CSV, Parquet, Hugging Face | Available | Available |
| No defaults | JSON/JSONL | Unavailable | Available |
| `cache` only | JSON/JSONL | Available | Available |
| `data` only | JSON/JSONL, CSV, Parquet, Hugging Face | Unavailable | Available |

The `cache` feature makes caching available; enable it on an LM with `.cache(true)`. That setting returns an error if the feature is absent. History remains available independently of caching.

## Complete example

Save this as `src/main.rs`. Set `OPENAI_API_KEY` in your environment before running `cargo run`. To preview the prompt offline, run `cargo run -- --inspect-only`; this sends no request and needs no key.

```rust
use dspy_rs::{LM, Predict, Signature};

/// Answer questions accurately and concisely.
#[derive(Signature, Clone, Debug)]
struct QA {
    #[input]
    question: String,
    #[output]
    answer: String,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let inspect_only = std::env::args().any(|arg| arg == "--inspect-only");
    let api_key = if inspect_only {
        "unused-for-prompt-inspection".to_string()
    } else {
        std::env::var("OPENAI_API_KEY")?
    };
    let lm = LM::builder()
        .model("openai:gpt-4o-mini".to_string())
        .api_key(api_key)
        .build()
        .await?;
    let predict = Predict::<QA>::builder().lm(lm.clone()).build();
    let input = QAInput {
        question: "What is the capital of France?".into(),
    };

    // Building a chat formats the prompt without sending a provider request.
    let chat = predict.build_chat(&input).await?;
    println!("{}", serde_json::to_string_pretty(&chat.to_json())?);
    if inspect_only {
        return Ok(());
    }

    let (prediction, _conversation) = predict.call_and_parse(chat).await?;
    println!("Answer: {}", prediction.answer);
    for entry in lm.inspect_history(1).await {
        println!("Raw output: {:?}", entry.raw_output);
        println!("Parsed output: {:?}", entry.output);
    }
    Ok(())
}
```

The same source is maintained as [00-quickstart.rs](https://github.com/krypticmouse/DSRs/blob/main/crates/dspy-rs/examples/00-quickstart.rs). From this repository, run `cargo run -p dspy-rs --no-default-features --example 00-quickstart -- --inspect-only`.

The derive generates `QAInput` and `QAOutput`. Struct documentation becomes the LM instruction; field documentation describes individual fields. The successful prediction contains `QAOutput`, accessed directly through `Deref`, and metadata via `.metadata()`. Use `.into_inner()` to take ownership of the output.

`build_chat` uses the configured LM to resolve the prompt but performs no provider request. Sending that same chat with `call_and_parse` avoids rebuilding the inspected prompt and returns the updated conversation. For a normal one-shot call, use `predict.call(input).await?`.

History records the executed call, its raw response and parsed output. Building a prompt alone does not create a history entry. History is bounded and is not persistent storage. See [LM history](/docs/components/lm#inspecting-history) for capacities, failure records and module scopes. Treat printed prompts and responses as potentially sensitive application data.

## Predictors and modules

A `Predict<QA>` is a module with one LM task. A `ChainOfThought<QA>` adds a typed reasoning field. Compose stages by implementing `Module::forward` and call the resulting module with `Module::call`. Declare its optimizer-visible leaves using `predictors!`.

See [Modules](/docs/components/modules) for a complete pipeline, [Predict](/docs/components/predict) for demos and validation retries, [Signatures](/docs/components/signatures) for custom types and constraints, and [LM](/docs/components/lm) for providers, scoped configuration and history. The [examples index](/docs/guides/examples) lists complete programs and their feature requirements.
