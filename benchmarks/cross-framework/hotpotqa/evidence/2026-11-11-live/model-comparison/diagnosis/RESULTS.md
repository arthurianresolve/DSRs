# DSRs reflection failure investigation

## Findings

The observed errors are generated by the model. DSRs passes the fixture and
intermediate values through correctly: the 18 baseline requests and model reply
texts reproduce the preceding native run exactly. All valid experimental
requests retain the exact question/context, and later stages receive their own
fresh draft and critique. The experiments are quality diagnostics, not latency
measurements or new native framework benchmarks.

Two distinct problems are visible:

1. **Incorrect self-criticism can damage a correct answer.** With the existing
   Qwen3-32B service, DSRs first answered `Animorphs` correctly. Its critic then
   incorrectly claimed that the question asked for the companion book, and the
   revision changed the answer to `The Hork-Bajir Chronicles`. The three exact
   replies are retained in `model-control-results.json`. This is a concrete
   failure of this reflection program, rather than a parser substitution.
2. **One question is underspecified.** The government-position question has
   several answers supported by its context: two ambassadorships and Chief of
   Protocol. The single unchanged reference accepts only the latter. A supported
   alternative remains a strict exact-match failure. This ambiguity does not
   explain the nationality or book/series mistakes.

The requested Qwen3-0.6B-Tasks model is also unreliable on this task. It can quote
that two people are American and nevertheless answer that their nationalities
differ. Prompt changes alone have not established a reliable fix. This evidence
does not prove that every possible prompt must fail or that parameter count is
the sole cause.

## Tested alternatives

The original three cases and strict references were retained. Three additional
synthetic cases check nationality, actor/role and companion-book/series relations
with different names and short contexts. They were fixed before these trials;
they are diagnostic examples, not a representative held-out benchmark.

| DSRs condition on Qwen3-0.6B-Tasks | Original final exact matches | Additional final exact matches |
| --- | --- | --- |
| Current native prompt, temperature 0, 128 tokens | 1/3 | 2/3 |
| Independent-check instructions | 1/3 | 1/3 |
| Non-thinking sampling, seed 0 | 0/3 | 2/3 |
| Non-thinking sampling, seed 1 | 1/3 | 2/3 |
| Non-thinking sampling, seed 2 | 1/3 | 1/3 |
| Thinking enabled, 1,024 tokens, seed 0 | 1/3 | Not run |
| Evidence-first typed outputs, 512 tokens | 0/3 | 0/3 |
| Concise prompt layout, original instructions | 0/3 | 2/3 |
| Full JSON prompt before the shortening optimization | 0/3 | 1/3 |

Some exact-match failures preserve the correct meaning; the raw answers remain
available. None of these conditions establishes a reliable correction of the
original DSRs workflow. In particular, restoring the full prompt does not support
reverting commit `c94ecb4fc42d789694c7e637b2324fc40b2819e9` as the fix for these
failures. The restoration reconstructs that method's full JSON prompt, keeping
inputs, task instructions, schema, temperature and token limit unchanged.

The sampling probes follow the [Qwen model card's settings](https://huggingface.co/Qwen/Qwen3-0.6B):
temperature 0.7/top-p 0.8/top-k 20/min-p 0 for non-thinking, and temperature
0.6/top-p 0.95/top-k 20/min-p 0 for thinking. These are explicit probes of the
user's existing model alias, not proof that its exact weights match the upstream
model card. No weights were downloaded or changed.

The earlier DSPy measurements are retained as controls. No DSPy implementation
or benchmark instruction was changed. Subsequent grounding, formatting, full
prompt and model-control experiments target DSRs only.

## Reflection correction rejected

A DSRs-specific candidate keeps the first-answer instruction unchanged. Its
critic must verify the question actually asked, accept a supported answer and
avoid inventing criticism. Its revision treats criticism as a suggestion and
keeps a correct supported draft. It did not fix the original failing case:

| DSRs condition | Original final exact matches | Additional final exact matches |
| --- | --- | --- |
| Existing 32B model, unchanged reflection | 1/3 | Not run |
| Existing 32B model, checked reflection | 1/3 | 3/3 |
| Requested 0.6B model, checked reflection | 0/3 | 1/3 |

The 32B model's correct `Animorphs` draft still became `The Hork-Bajir Chronicles`.
The 0.6B model regressed on the nationality question. The change was therefore
rejected. No runtime prompt or adapter patch is justified by these trials, and
the answer-quality problem remains unresolved. This investigation has not found
a reliably passing DSRs configuration or reflection correction.

The engineering implication is that this program cannot treat the model's own
criticism as a reliable verifier. A future correction needs an independently
validated acceptance rule for revisions and a clearly specified evaluation
fixture. That rule must use information available at inference time; the scoring
references in these experiments remain evaluation-only. This is a next design
requirement, not an implemented or verified fix.

## Evidence and scope

`bundle.json` contains the frozen native request templates and experimental
instructions. `references.json` contains scoring references; they were excluded
from the inference bundle. The remote runners capture each fresh model reply
before supplying the next stage. `analysis.json` retains draft/final scores and
exact answers; `verify.py` reproduces the checks. Raw JSON, model identities,
sampling settings, stop reasons and reasoning text are retained in the result
files. The original performance measurements and reference scores are unchanged.

There are 297 valid real-provider requests in this investigation: 198 for DSRs
and 99 earlier DSPy controls. All stopped normally. The first 18-request small
checked-reflection attempt is retained separately as an **invalid encoding
diagnostic**: its runner decoded UTF-8 source using the Windows locale and changed
punctuation in fixture inputs. Input verification caught the mismatch. The fixed
UTF-8 rerun preserves the exact fixture and supplies the reported small-model
scores; the invalid attempt is excluded from the 297 requests above.

The ten named temporary diagnostic directories were removed only after retained
files matched their remote SHA-256 checksums. Both pre-existing model containers
were still running after cleanup. No model weights or persistent service
configuration were changed.

Browser/guest-agent transport and serial fixed ordering prohibit latency claims.
The small, deliberately diagnostic sample also prohibits general model rankings
or a claim of universal quality or speedup.
